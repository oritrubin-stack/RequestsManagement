
# Project Instructions

## Project
We are building a full-stack request management system as a technical take-home assignment.

- Backend: .NET 8 Web API
- Frontend: Angular
- Database: To be selected after evaluating the assignment requirements.
- Current backend project: RequestsManagement.Api

## Working Rules

- Explain the purpose and reasoning behind each significant implementation decision.
- Work in small, reviewable steps.
- Do not modify files until I explicitly approve the proposed changes.
- Before each implementation task, explain the plan and list the files expected to change.
- Do not perform broad refactoring or rename existing code without approval.
- Do not install packages, change project configuration, or create additional projects without approval.
- Never commit, push, deploy, or modify a remote server without explicit approval.
- Never expose secrets, credentials, or connection strings.

## Code Quality

- Use asynchronous APIs where appropriate.
- Follow dependency injection and separation of concerns.
- Validate inputs and handle errors consistently.
- Use DTOs for API responses rather than exposing database entities.
- Consider performance, cancellation, concurrency, and testability.
- Do not claim that code or tests work unless they have actually been checked.

## Workflow

For every task:
1. Inspect the relevant existing code.
2. Explain the proposed solution and alternatives.
3. Wait for approval before editing files.
4. Make only the approved changes.
5. Report changed files and explain the changes.
6. Suggest verification steps and report actual test results.

## Communication

Communicate in Hebrew. Keep code identifiers and code comments in English.
